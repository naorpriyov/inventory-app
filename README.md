# ניהול מלאי וספר סמים – גרסה עצמאית

התוכנה רצה על שרת משלכם, נפתחת בכל דפדפן ואפשר להתקין אותה בטלפון כמו אפליקציה. היא לא תלויה ב־Claude או בשירות חיצוני אחר.

## מה יש בתיקייה

| קובץ | מה הוא עושה |
|---|---|
| `app.py` | השרת (Python + Flask). שומר את הנתונים, מנהל משתמשים, בודק הרשאות וקובע את היתרות בספר הסמים |
| `reports.py` | הדוח החודשי |
| `push_notify.py` | התראות לטלפון |
| `static/index.html` | מבנה העמוד של התוכנה |
| `static/css/` | העיצוב (`app.css`, ו־`sign.css` לפתק ההחתמה) |
| `static/js/app.js` | הלוגיקה: מסכים, מלאי, פקלי סמים, ספר סמים, הרשאות וגרפים |
| `static/js/sign.js` | פתק ההחתמה וה־PDF שלו |
| `static/shim.js` | החיבור לשרת, חשבונות משתמשים, יומן ביקורת והתראות |
| `static/fonts/`, `static/vendor/` | הגופן וספריית ה־PDF, שמורים מקומית כדי שהתוכנה לא תלויה באתרים חיצוניים |
| `static/auth.html` | מסכי כניסה, הרשמה והגדרה ראשונה |
| `static/sw.js`, `static/manifest.webmanifest`, `static/icons/` | התקנה כאפליקציה בטלפון וקבלת התראות |
| `tests/run_tests.py` | בדיקות אוטומטיות. מריצים לפני כל עדכון: `python tests/run_tests.py` |
| `data/` | מסד הנתונים (`inventory.db`), המפתחות והדוחות החודשיים. זו התיקייה שמגבים |

## הרצה ראשונה על המחשב שלך

1. מתקינים Python 3.10 ומעלה מ־python.org. בהתקנה ב־Windows מסמנים "Add Python to PATH".
2. ב־Windows לוחצים פעמיים על `start-windows.bat`. במק או לינוקס מריצים `./start-mac-linux.sh`.
3. פותחים בדפדפן את הכתובת `http://localhost:8000`.
4. בכניסה הראשונה נפתח מסך "הגדרה ראשונה". יוצרים בו את חשבון המנהל, כלומר את החשבון שלך.

## ניהול משתמשים

1. **קוד הרשמה:** בראש התוכנה לוחצים "חשבונות משתמשים" ורואים את קוד ההרשמה. מוסרים אותו לעובדים.
2. **הרשמת עובד:** העובד נכנס לכתובת, לוחץ "הרשמה" וממלא קוד הרשמה, שם משתמש וסיסמה. שם המשתמש הוא גם השם שמוצג בתוכנה.
3. **בקשת הרשאות:** הבקשה נשלחת למנהל אוטומטית בזמן ההרשמה. עד שהמנהל מאשר, העובד רואה את המסך "אין עדיין גישה למסכים". אם המנהל דחה את הבקשה, העובד יכול לשלוח בקשה חדשה מאותו מסך.
4. **אישור:** המנהל לוחץ בלשונית "מלאי" על "הרשאות משתמשים" ומאשר את הבקשה. עובד שאושר מתחיל בלי גישה לאף מסך.
5. **גישה למסכים:** באותו חלון קובעים לעובד, לכל אחד מששת המסכים (לוח בקרה, מלאי, החתמה, ספר סמים, ספירת מלאי, מיקומים וערכות), אחת משלוש רמות:
   - **ללא גישה:** המסך לא מופיע לעובד, והשרת לא שולח לו את הנתונים שלו.
   - **צפייה בלבד:** העובד רואה את המסך, בלי כפתורים שמשנים נתונים. ייצוא ל־CSV נשאר זמין.
   - **גישה מלאה:** העובד יכול לפעול במסך.
6. **פעולות מותרות:** בנוסף, מסמנים אילו פעולות מותרות לעובד במסכים שיש לו בהם גישה מלאה: קבלת מלאי, הורדה, עריכה וספירת מלאי.
7. **ניהול חשבונות:** בחלון "חשבונות משתמשים" אפשר לאפס סיסמה, לחסום עובד, להפוך עובד למנהל וליצור קוד הרשמה חדש. יצירת קוד חדש מבטלת את הקוד הקודם.

שינוי הרשאות נכנס לתוקף אצל העובד תוך כמה שניות, בלי שהוא צריך לרענן. החתמה, מכל מסך, דורשת גישה מלאה למסך "החתמה".

### מה השרת אוכף בעצמו

את הכללים האלה השרת בודק בעצמו, כך שאי אפשר לעקוף אותם גם בלי המסכים:

- **גישה למסכים:** עובד בלי גישה לאף מסך לא מקבל שום נתון. עובד עם צפייה בלבד לא יכול לשנות נתונים. ספירות מלאי נשמרות רק עם גישה מלאה ל"ספירת מלאי", מיקומים חדשים רק עם גישה מלאה ל"מיקומים וערכות", ופתקי החתמה רק עם גישה מלאה ל"החתמה".
- **פתקי החתמה:** רק המנהל רואה פתקים של אחרים, ורק הוא יכול לזכות פתק.
- **הרשאות:** רק המנהל מאשר הרשאות וקובע גישה למסכים. עובד יכול רק לשלוח בקשה לעצמו, ולא רואה את ההרשאות של אחרים.
- **מחיקה:** מחיקת פריטים, ערכות ומיקומים מותרת רק למי שיש לו הרשאת "עריכה".
- **ספר הסמים:** השרת קובע בעצמו את הזמן, את המשתמש ואת היתרות של כל רישום, ולא סומך על הדפדפן. כמות שלילית או לא שלמה נדחית.
- **רשומות שלא משתנות:** רשומות ספר הסמים, הספירות והזיכויים נכתבות פעם אחת, ואי אפשר לשנות או למחוק אותן.
- **חסימה:** משתמש חסום לא יכול להיכנס.

שינויי כמות בפריטים פתוחים לכל עובד שיש לו גישה מלאה לפחות למסך אחד, כי ההחתמה צריכה להוריד מהמלאי. הכפתורים "הוספה" ו"הורדה" מוסתרים במסכים ממי שאין לו הרשאה.

## פקלי סמים (קופסאות ממוספרות)

המסך "פקלי סמים" מנהל את הקופסאות הסגורות (למשל SA1–SA100, SAH1–SAH20). החתימה של הרופא נשארת על הנייר, והתוכנה עוקבת אחרי הקופסאות והכמויות.

- **שלושה מצבים בלבד:** בכספת (מלאה), חתומה (יצאה), ריקה. אין קופסה חלקית.
- **מיקום:** לכל קופסה בוחרים כספת (קידמית, אחורית או מיקום אחר), ואפשר להעביר כמה קופסאות יחד.
- **תוקף:** לכל סם בקופסה נשמרים אצווה ותוקף. במילוי מהמלאי הם נרשמים לבד. בקופסאות שהוכנסו כמלאות רושמים את התוקף ידנית ("עריכת מיקום ותוקף"). קופסה עם סם שפג תוקפו או פג החודש מסומנת.
- **חזרה פתוחה:** רושמים מה נוצל. מה שלא נוצל חוזר למלאי החופשי, לאותה אצווה, והקופסה הופכת לריקה.
- **מילוי:** קופסה ריקה מתמלאת מהמלאי החופשי לפי התבנית, מהאצוות עם התוקף הקרוב ביותר. אצוות שפג תוקפן לא נלקחות.
- **ספר הסמים:** מילוי, שימוש והחזרה נרשמים בספר הסמים. העמודה "מלאי בערכות" כוללת את הקופסאות המלאות והחתומות.
- **התחלה:** "הוספת קופסאות" עם האפשרות "מלאות כבר עכשיו" רושמת את הקופסאות הקיימות בלי להוריד מהמלאי.
- **הרשאות:** המסך מופיע בחלון ההרשאות כמו כל מסך אחר. מחיקת קופסה ריקה דורשת את הרשאת "עריכה".

## לוח בקרה, דוחות והתראות

- **גרפים בלוח הבקרה:**
  - "צריכה חודשית לפי סם": החתמות, החתמות מערכות ושימוש מפקלים, פחות זיכויים, ב־6 החודשים האחרונים. לכל סם גרף קטן, ולכולם אותו קנה מידה.
  - "איפה נמצאים הסמים": מלאי חופשי מול ערכות ופקלים.
  - נגיעה או ריחוף מראים את המספר. הכפתור "טבלה" מציג את אותם נתונים כטבלה.
- **דוח חודשי:** במסך "ספר סמים" לוחצים "דוח חודשי" ובוחרים חודש. הדוח כולל:
  - יתרות בתחילת החודש ובסופו, קבלות, החתמות, שימוש מפקלים, זיכויים והתאמות.
  - ספירות שבוצעו בחודש.
  - תוקפים ומצב הפקלים.
  
  מהדוח אפשר להדפיס או לשמור כ־PDF. בתחילת כל חודש נשמר אוטומטית עותק של הדוח של החודש הקודם ב־`dataeports`.
- **התראות לטלפון:**
  - **הפעלה:** לוחצים "התראות" בראש התוכנה ← "הפעלת התראות במכשיר הזה". באייפון זה עובד רק מהאפליקציה המותקנת ("הוסף למסך הבית").
  - **תזכורת יומית:** פעם ביום, מ־08:00, מגיעה תזכורת אם יש מה לטפל בו: תוקף, מלאי נמוך, פקלים חתומים יותר משבועיים או פקלים ריקים. בתחילת החודש מגיעה גם הודעה שהדוח מוכן.
  - **פרטיות:** בהתראות אין פרטים אישיים.
  - **מי מקבל מה:** כל עובד מקבל רק את מה שרלוונטי למסכים שיש לו גישה אליהם.
- **יומן ביקורת:** בחלון "חשבונות משתמשים" ← "יומן ביקורת". כל שינוי בנתונים וכל ניסיון כניסה נרשמים עם מי ומתי. אי אפשר למחוק את היומן או לשנות אותו.

## גישה מהטלפון והתקנה כאפליקציה

כדי שהטלפונים יגיעו לשרת, הוא צריך לרוץ על מחשב או שרת שזמין להם.

- **ברשת פנימית (Wi‑Fi של היחידה):** מריצים את השרת על מחשב קבוע, ונכנסים מהטלפון לכתובת `http://<כתובת-המחשב>:8000`. את כתובת המחשב מוצאים ב־Windows עם הפקודה `ipconfig`.
- **התקנה מלאה כאפליקציה:** אפליקציה עם אייקון שנפתחת במסך מלא דורשת כתובת מאובטחת, כלומר כתובת שמתחילה ב־`https://`. מקבלים אותה כשהשרת יושב מאחורי שרת ארגוני עם תעודת אבטחה, או בשירות אחסון כמו Render, Railway או PythonAnywhere. במצב הזה מגדירים את משתנה הסביבה `INV_HTTPS=1`.

אחרי שיש כתובת `https`, מתקינים בטלפון:
- **אייפון:** פותחים ב־Safari, לוחצים על כפתור השיתוף ובוחרים "הוסף למסך הבית".
- **אנדרואיד:** פותחים ב־Chrome, פותחים את התפריט ובוחרים "התקנת אפליקציה" או "הוספה למסך הבית".

## גיבוי

- **גיבוי אוטומטי:** כל יום, כשהשרת פועל, נשמר עותק של מסד הנתונים בתיקייה `backups\auto` (בתוך תיקיית התוכנה). נשמרים 30 הימים האחרונים, והישנים נמחקים לבד. מועד הגיבוי האחרון מופיע אצל המנהל בחלון "חשבונות משתמשים".
- **שחזור:** סוגרים את חלון השרת ומריצים `python restore_backup.py`. בוחרים את היום, ומאשרים. מסד הנתונים הנוכחי לא נמחק אלא נשמר בתיקייה `backups`. אחר כך מפעילים את השרת מחדש.
- **גיבוי מחוץ למחשב:** הגיבוי האוטומטי יושב על אותו מחשב, ולכן לא מגן מפני תקלה בדיסק או גניבה. כדאי להגדיר את משתנה הסביבה `INV_BACKUP_DIR` לתיקייה בדיסק חיצוני או בכונן מוצפן, או להעתיק את `backups\auto` לשם מדי פעם.
- **גיבוי מלא:** מעתיקים את התיקייה `data` כשהשרת כבוי. זה כל המידע.
- **גיבוי מתוך התוכנה:** הכפתור "גיבוי" בלוח הבקרה שומר קובץ JSON.

## הפעלה אוטומטית ברקע

השרת עולה לבד, בלי חלון, ברגע שהמחשב נדלק, גם לפני שמישהו נכנס ל־Windows. זו משימה מתוזמנת בשם `InventoryServer`.

- **אם השרת נופל:** הוא חוזר לבד תוך כמה שניות. אם גם תהליך השמירה שלו נסגר, Windows מפעיל הכול מחדש תוך 5 דקות.
- **הפעלה מחדש,** למשל אחרי עדכון: `server-restart.bat`.
- **עצירה:** `server-stop.bat`. זו עצירה זמנית, כי הבדיקה של Windows מפעילה את השרת שוב תוך 5 דקות. לעצירה קבועה מבטלים את ההפעלה האוטומטית.
- **יומן:** כל ההודעות של השרת נכתבות ל־`logs\server.log`.
- **הגדרה במחשב חדש:** לוחצים פעמיים על `enable-always-on.bat` ומאשרים את חלון Windows. בלי הרשאת מנהל אפשר להשתמש ב־`powershell -ExecutionPolicy Bypass -File setup-autostart.ps1`, ואז השרת עולה רק אחרי כניסה ל־Windows.
- **ביטול ההפעלה האוטומטית:** `powershell -ExecutionPolicy Bypass -File setup-autostart.ps1 -Remove`. ההפעלה הידנית עם `start-public.bat` ממשיכה לעבוד.

השרת פועל רק כשהמחשב דולק ומחובר לאינטרנט. כרגע המחשב מוגדר לא להיכנס לשינה, וכדאי להשאיר את זה כך.

## כתובת האתר

הכתובת הקבועה שמורה בתיקיית התוכנה בשני קבצים:
- **`כתובת האתר.url`:** לחיצה כפולה פותחת את האתר.
- **`כתובת האתר.txt`:** הכתובת כטקסט, להעתקה ולשליחה לעובדים.

בכל הפעלה של `start-public.bat` הכתובת נבדקת מול Tailscale, והקבצים מתעדכנים לבד אם היא השתנתה, למשל אחרי מעבר למחשב חדש. הכתובת מופיעה גם בחלון השרת.

## העברה למחשב אחר

1. **במחשב הישן:** לוחצים פעמיים על `pack-for-move.bat`. על שולחן העבודה נוצר קובץ `inventory-move-<תאריך>.zip` עם התוכנה, כל הנתונים ומפתח הכניסות. אפשר להריץ אותו גם כשהשרת פועל.
2. **מעבירים את הקובץ** בדרך מאובטחת (דיסק און קי שלך, לא מייל). יש בו נתונים רגישים.
3. **במחשב החדש:** מחלצים את הקובץ ולוחצים פעמיים על `setup-new-computer.bat`. הוא מתקין את Python, את החבילות ואת Tailscale, ומסביר מה נשאר.
4. **שומרים על אותה כתובת:** נכנסים ל־Tailscale עם אותו חשבון. בדף הניהול מוחקים את המחשב הישן, ונותנים למחשב החדש את השם `cnd03720l6`. כך הטלפונים ממשיכים לעבוד בלי שינוי.
5. **מפעילים** את `start-public.bat`. במחשב הישן לא מפעילים יותר את השרת, ובסוף מוחקים ממנו את התיקייה ואת קובץ ה־zip.

## אבטחה

- **ניחוש סיסמאות:** אחרי 8 סיסמאות שגויות לאותו משתמש, הכניסה אליו ננעלת ל־15 דקות. אחרי 10 ניסיונות שגויים של קוד הרשמה מאותה כתובת, גם ההרשמה ממנה ננעלת.
- **החלפת סיסמה:** כשמחליפים סיסמה, או כשהמנהל מאפס אותה, כל החיבורים של המשתמש במכשירים אחרים מתנתקים.
- **נתונים לפי מסך:** ספר הסמים והזיכויים נשלחים רק למי שיש לו גישה ל"ספר סמים". פרטי המטפלים, כולל מספרי זהות, רק למי שיש לו גישה ל"החתמה". ספירות רק למי שיש לו גישה ל"ספירת מלאי" או ל"לוח בקרה".
- **גישה רק בכתובת המאובטחת:** בהפעלה הציבורית (ברקע או עם `start-public.bat`), השרת מאזין רק למחשב עצמו (`127.0.0.1`). מבחוץ אפשר להגיע אליו רק דרך הכתובת המאובטחת של Tailscale, ולא דרך הרשת המקומית בלי הצפנה.
- **הגנות דפדפן:** השרת חוסם בקשות שמגיעות מאתרים אחרים, לא מאפשר להטמיע את התוכנה בתוך אתר אחר, ומחייב https בכתובת הקבועה.

## הגדרות (משתני סביבה, לא חובה)

| משתנה | ברירת מחדל | מה הוא קובע |
|---|---|---|
| `INV_PORT` | `8000` | הפורט שעליו השרת רץ |
| `INV_HOST` | `0.0.0.0` | הכתובת שהשרת מאזין לה |
| `INV_DATA_DIR` | `./data` | איפה נשמרים הנתונים |
| `INV_HTTPS` | (ריק) | `1` כשהשרת רץ מאחורי `https` |
| `INV_BACKUP_DIR` | `./backups/auto` | איפה נשמרים הגיבויים היומיים |
| `INV_BACKUP_KEEP` | `30` | כמה גיבויים יומיים לשמור |

## חשוב לפני שימוש אמיתי

התוכנה שומרת רישום סמים מבוקרים, שמות, מספרים אישיים וחתימות. לפני שמכניסים נתונים אמיתיים, צריך לבדוק עם הגורם האחראי על אבטחת מידע איפה מותר להריץ את השרת. גם כשהשרת ברשת פנימית, חשוב לגבות את `data` באופן קבוע.

- **השהיה בעדכונים:** עדכונים ממשתמשים אחרים מופיעים אחרי כ־3 שניות.
